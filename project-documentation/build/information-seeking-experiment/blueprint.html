Blueprint: the bias experiment tool

A reader can tell what each part does, what passes between the parts, and where the line is that nothing may cross.

The browser tool that runs the week 3 in-class experiment on biased information seeking: sixteen source cards, a budget of eight, two rounds, one line of result per student, and a lecturer view that aggregates thirty-two of them into a paired comparison.

This document describes the finished thing only. It carries no order of work, no phases and no record of what is built — those belong to the build plan, which is the state. When the two disagree, this document is the intent and the code is the backlog.

2 · The goal

One two-round experiment runs end to end for 32 students inside a 150-minute block, on the students’ own laptops, with every card choice and the order it was shown in recorded, no request leaving any browser, and 32 result lines turned into one paired comparison in under 10 minutes.

Every rule below serves some part of that sentence, and every part of that sentence is covered by a rule. The trace is in §8.

3 · The parts

One HTML file, four things inside it.

PartDoesKnows nothing about
Card deckHolds 32 cards as data: 2 claims × 16. Title, APA reference, teaser, extract, link.Which cell a card belongs to. The deck in the published page carries no stance or quality label.
Session runnerConsent, position, shuffle, the budget of 8, the agent step, the closing questions. Writes one result line.What the numbers mean. It counts; it does not judge.
Result lineThe only thing that crosses between a student and the class. One line of text, copied by hand.Who the student is. It carries a self-chosen code.
ServiceTakes one submission of numbers, stores it for the day, aggregates on request. Two routes and nothing else.Anything a student wrote. No sentence ever reaches it.
DashboardOwners only. Draws the comparison live, and states which of a fixed set of sentences the interval permits.How to write its own sentence. It selects; it does not compose.
Lecturer paste viewThe fallback when the service is down: takes pasted lines and does the same arithmetic offline.How to state a conclusion. It has no sentence that concludes.

The codebook — which card is congenial, which is strong — is not in the card deck. site/ is a public URL from a public repository, so a label in the page is a label a student can read before the session. The lecturer view takes the codebook as pasted input at analysis time.

4 · The flow of one student’s session

consent + code + team
      ↓
ROUND 1 ── claim A ── position (locked) ── [agent?] ── 16 cards shuffled ── open ≤ 8
                   ── final position ── closing questions
      ↓
ROUND 2 ── claim B ── position (locked) ── [agent?] ── 16 cards shuffled ── open ≤ 8
                   ── final position ── closing questions
      ↓
one result line ──[ Submit ]──> service ──> dashboard (owners only)
                 └──copy by hand──> paste box, when the service is down

The agent appears in exactly one of the two rounds. Which one depends on the team number, so that half the room meets it first and half meets it second.

The agent sits between the locked position and the first card, and that placement is load-bearing. What is measured is which sources a student opens, so the agent has to speak while that choice is still ahead of them. Placed after the menu it could not move the measurement at all.

6 · Rules

Obligation is the product’s obligation, not the order of work. Every criterion carries a number and a unit; every rule names how it is shown to hold. One rule, one obligation, one way to fail — a rule that could fail for two unrelated reasons has been split rather than reworded, and new rules are appended to their group so that an identifier never changes meaning.

7 · What the wiring enforces

Three properties hold because of how the parts are arranged, not because anyone remembers them.

  • Nothing can leak. The tool makes no request, so there is no path by which a student’s typing reaches anyone. Withdrawal is closing a tab.
  • The experiment cannot be read in advance. The stance and quality labels are not in the file that ships, so a student who opens the source sees sixteen cards and no answer key.
  • The tool cannot conclude. It holds no sentence that states a finding, so the conclusion has to be written by a person.

9 · Deliberate exclusions

Not “not yet” — never, unless this document changes.

  • Calling a model. The agent runs in the student’s own assistant.
  • Writing the conclusion. Stating a finding would put the verdict-giving behaviour the experiment is testing inside the instrument that measures it.
  • Scoring a student. ADR-0011 keeps the week’s gates unscored, and this is not a way round that.
  • An account for a student, or sync between their devices. The service knows a self-chosen code and nothing that identifies anyone.
  • Retaining data beyond the teaching day. A scheduled purge, per ADR-0016, not an intention.
  • A model writing the interpretation. The dashboard selects a sentence the interval permits; it does not compose one.
  • A general survey builder. Two claims, sixteen cards each.

10 · Open questions

  • Where the codebook lives at analysis time. SM-8 keeps the labels out of the page; the lecturer view therefore needs them pasted, held in a separate file, or applied afterwards in a spreadsheet. Owner: the module owners.
  • The floor on opens. A student who passes over nine cards reaches the end with budget unspent. Whether an index computed over three opens is comparable with one over eight is unresolved. Owner: the AIBS owner.
  • Both claims are unchosen. The CL rules say what they must satisfy; finding two that do is the open work. Owner: the AIBS owner.

What can run in parallel

Derived from which files each phase writes, because merge conflicts happen per file.

FileWritten by
provenance.mdPhase 0 only
site/week-03-slides.htmlPhases 1 and 2 — and whoever builds the rest of the week 3 deck
project-documentation/slides/week-03-notes.mdPhases 0 and 3 — and the rest of the week 3 deck
site/week-03-deck.html, PDF, PPTXPhase 3 — generated, so a conflict is settled by rebuilding
project-documentation/worklog.mdPhases 2 and 4 — and every other piece of work in the repository
  • Phase 0’s provenance work runs beside anything. It writes one file nobody else touches.
  • Subtask 3.1 runs beside anything. .venv is not content.
  • Phases 1 and 2 cannot run beside the rest of the week 3 deck. Both write site/week-03-slides.html. Whoever creates that file first fixes its shell and card numbering; agree who before either starts, because the shell and the numbering are the interface to settle first.
  • The worklog is shared by everything. Add rows at the end of a phase, pull main first, and expect a merge.

What this plan does not do

  • It does not build the rest of the week 3 deck, the week 3 page or the session plan.
  • It does not publish the week 3 page or link the deck from the landing page’s week map: the two-edit publication step in CLAUDE.md, done when the week goes live.
  • It does not change the experiment. The segment adapts to the experiment, never the other way round.
  • It does not write AI Wiki pages. The two gaps the query found are recorded in the PRD.
  • It does not merge. The work sits on a branch until the link check is green and a pull request is open, as CLAUDE.md requires.
